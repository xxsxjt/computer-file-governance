# Windows 本机 Profile

本 profile 描述治理时需要核实的 Windows 特性，不规定固定盘符或统一目录布局。

## 盘点前

- 核实实际 Windows 身份、`USERPROFILE` 和 Known Folder 解析结果；不能因某个用户路径存在就认定它属于当前用户。
- 识别 Junction、符号链接、挂载点、卷标、文件系统和重解析属性。默认列出链接本身，不沿链接递归。
- 明确哪些是个人数据、项目源、生成输出、应用状态、下载收件箱、备份或可重建缓存，并确认应用/服务是否仍引用原路径。
- 遵循当前工具对 Windows ACL、备用数据流、时间戳和文件锁的保留能力；不支持时需说明保证缺口。

## 默认保护范围

Windows、Program Files、ProgramData、用户配置/凭据目录、OneDrive/其他同步根、虚拟机目录、数据库和应用自身管理的目录均需先确认 owner、依赖和恢复方式。不得把用户目录中看似缓存或旧版本的内容直接视为垃圾。

Downloads 可作为按需分拣的收件箱；临时、未完成、用途不明或仍可能被 VM/安装器引用的文件保留在原位。桌面、项目树及同步目录不应用通用“清理”规则批量迁移。

## 变更与验证

- 先预览直属项；只有用户授权的根目录可按限额扩展递归。
- 不覆盖、不永久删除；同卷移动也要记录来源与目标。跨卷操作先复制并校验内容与必要元数据，目标确认可用后才考虑单独授权的源清理。
- 对被快捷方式、配置、VMX、任务计划或应用数据库引用的路径，先搜索并验证依赖，不擅自改引用。
- 验证目标存在、大小/哈希相符、访问权限和关键引用正确；记录事务 manifest 和回滚步骤到本机受限位置。
