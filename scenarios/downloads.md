# Downloads 收件箱场景

Downloads 是收件箱，不是必须清空的暂存区。目标是在保留临时工作和未完成下载的同时，让有持续价值的安装器、资料和交付物进入合适的规范位置。

## 分类

按用途与持续价值判断，而不是按扩展名或年龄一刀切：

- 可复用的安装介质、项目依赖快照和已验证归档：识别来源、版本、校验值、owner 与目标角色。
- 项目输入、研究资料和已完成交付物：归入其项目/主题事实源，并在索引中保留可检索引用。
- 未完成、仍在下载、待审阅、临时转换产物及用途不明项：保持原位，记录为待处理，而不是为了“整洁”而搬走。
- 可证明重复的文件：先比较完整哈希及来源/依赖关系；重复不自动等于可删除，仍需确认是否为回滚副本或应用引用目标。

## 访问范围与信任

- 对整个 Downloads 根目录进行任何枚举、搜索或盘点（包括只列直属项的浅层预览）都属于受限操作。只有本机明确指定的隐私主管 Agent，在本机私有信任策略明确标记为可信的模型渠道上，且当前任务授权完整根目录范围，才可执行。递归盘点还必须单独限定深度、类型或其他上限。
- 其他 Agent 或使用非可信模型渠道的 Agent 不得枚举、搜索、glob 或递归扫描 Downloads 根目录。它们只能在任务明确提供的具体文件路径或根目录下明确子文件夹范围内操作，不得枚举或搜索根目录、父目录、同级项目或任务未提供路径。只提供 Downloads 根路径本身，不授权它们盘点整个目录。
- 具体路径授权只限定可操作范围；是否读取或向模型渠道发送文件正文、名称或元数据，仍须按文件隐私分类和任务授权判断，并尽量只返回完成任务所需的最少信息。若需要先发现候选项，应交由本机隐私主管 Agent 在可信渠道上按授权盘点，再只交付执行所需的精确路径和最少信息。

## 执行要求

1. 先按“访问范围与信任”确认当前 Agent、模型渠道和具体路径；只有本机隐私主管 Agent 在可信渠道且任务授权完整根目录时才可使用根目录预览。递归盘点仍须先限定范围和上限。
2. 完整根目录操作由本机隐私主管 Agent 核实 Known Folder、junction/symlink 指向和实际目标账户；路径存在不等于属于当前用户。其他 Agent/渠道只操作任务给出的精确路径，不自行发现或枚举 Downloads 根目录。
3. 先提交分类与 dry-run 计划；不覆盖目标、不永久删除、不修改快捷方式或应用/VM 配置。
4. 依据当前用户文本指令或适用的明确规则移动文件；不要求每批单独 UI/RPC 确认。跨卷时复制并验证目标，源清理作为独立动作；回收站处理只可在明确指令下使用 Windows Recycle Bin，不永久删除或清空回收站。
5. 记录事务 manifest、哈希/大小验证、回滚路径和更新后的本地索引。

整洁度不是成功指标；高价值项目归档、未知项安全保留、索引准确且可恢复，才是治理结果。
