# Agent Adapters

核心规则只有一份：根目录的 `SKILL.md`。本目录用于把同一规则接入各 Agent，不复制或分叉政策正文。

## 推荐接入方式

- 支持 Agent Skills 的 Agent：把本仓库作为一个 skill 安装/引用；确保 `SKILL.md` 的相对链接及被引用的 `docs/`、`profiles/`、`scenarios/` 随安装保留。
- 仅支持项目指令文件的 Agent：在其官方项目指令入口中加入一条简短引用，指向 `SKILL.md`，并要求任务触发时再读取对应 profile。不要把全部治理文档粘贴到另一份规则文件中。
- 支持工具/插件扩展的 Agent：实现只读盘点、dry-run 展示、确认和事务记录接口时，仍将本 Skill 作为行为规范；工具不得以模型指令替代 OS 权限或目标端授权。

安装目录和配置键会随 Agent 版本变化。发布新的具体安装指令前，先核对相应 Agent 的官方文档与当前稳定版；不要把某个 Agent 私有 API 描述成跨 Agent 标准。

## 适配器接口建议

一个文件治理 adapter 至少应能表达：

- 授权根目录与排除项；直属或有界递归的元数据预览；链接/挂载识别。
- 候选变更 dry-run、目标冲突拒绝、明确的用户确认；无 UI 时 fail closed。
- 批次 ID、跨进程互斥、来源/目标记录、结果校验、回滚或 `OUTCOME_UNKNOWN`。
- 私有本地索引与 manifest 的持久化路径；日志和错误信息脱敏。

公开 adapter 实现不得包含真实机器路径、用户身份、远程主机、授权令牌或实际文件清单。
