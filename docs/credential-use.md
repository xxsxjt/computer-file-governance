# 不向模型提供商暴露明文凭据

## 目的

本规范保护的是凭据不进入模型提供商可见的提示词、工具参数、工具结果、配置或日志；它不是用来防止 Agent 在本机调用用户授权的能力，也不以模型提供商是否“可信”作为单独拒绝理由。

## 调用方式

1. Agent 按用户授权发起正常操作，例如访问仓库、创建资源或推送已审核内容。工具参数只含完成操作所需的非凭据字段。
2. 本机 vault-backed adapter 在本机解析凭据，并直接用于目标服务的认证请求。凭据可以短暂存在于本机 adapter 的进程内存中；不返回给 Agent，也不要求 Agent 读取、粘贴或传递明文。
3. Adapter 返回完成操作所需的普通状态和结果。凭据值、Authorization header、解析输出及含凭据的调试信息不得进入模型可见内容、终端输出、Agent 配置或日志。
4. 操作仍遵循用户任务授权和已有工具正常的确认流程。仅因 Agent 所用的模型提供商不受信任，不应拒绝它调用已配置的本机 adapter。

## 可见性边界

- 模型提供商仍可见普通工具调用参数和返回内容，例如仓库名、文件内容、API 返回数据及操作状态。隐藏 Token 不会自动隐藏这些数据；仍按对应数据的隐私等级判断是否可发送给该模型。
- 目标服务会收到用于认证的凭据或认证头，这是 API/Git 操作成立所必需的传输；要求使用 HTTPS 等目标服务认可的安全通道。
- Adapter 使用已配置凭据，不会自动缩小其服务端权限范围。Token 的实际权限仍由 GitHub/vault 中的凭据设置决定。
- 本规范不声称能阻止恶意本机 Agent、同一用户下的进程或拥有本机权限的人使用本机能力；防止这类本机访问不属于本规范目标。
- 文档本身不会创建工具能力。目标 Agent 必须已配置可调用的本机 adapter；如果没有相应工具，就不能仅凭阅读本文件执行操作，也不应要求用户把 Token 粘贴给模型。

## GitHub 示例

Agent 需要访问 GitHub 时，向本机已配置的 GitHub adapter 提交仓库和操作参数。Adapter 在本机使用 vault-backed 凭据发起 GitHub API/Git 请求，再返回状态和必要结果。Agent 不获得 Token 字符串；模型提供商仍会看到 Agent 发送的仓库名、请求内容及 adapter 返回的普通数据。

文件治理任务中，提交 GitHub 前还要遵循核心 Skill：盘点待提交文件、检查隐私与凭据、验证目标内容和提交结果，并把机器专属目录清单、私人索引及实际 manifest 留在本机。
