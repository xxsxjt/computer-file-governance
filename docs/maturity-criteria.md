# 成熟度标准

本文定义本框架「成熟」的含义。它不是完成声明，也不是整理率口号；当前完成情况以本地执行台账、测试输出和发布包检查为准。公开仓库只保存通用规范、schema、代码与合成夹具，不保存任何机器的真实清单、会话、凭据或证据正文。

## 1. 产品定义

目标：让整台电脑上的人和多个 Agent 能够按统一规则治理文件、共享信息、通过统一索引查找内容、放置工作产物，并在需要时通过不暴露明文凭据的宿主适配器调用已授权服务。整理动作只是达成目标的一种手段，移动数量、删除数量、目录美观程度都不是成功指标。

四层成熟度必须分别判断：全机文件治理规范、全机统一索引与信息共享、Agent 工作区/产物边界、vault-backed 非明文调用。前两层是产品主线，后两层是运营与安全支撑。公开仓库中的规范合同、参考实现和宿主实际部署是三种不同状态；Schema 通过、代码存在或 worker 报告完成，都不能替代宿主验证。

非目标：

1. 不自动清空、去重、删除或集中所有文件。
2. 不绕过操作系统权限、应用所有权、服务端授权或平台确认。
3. 不把本机真实路径、个人清单、运行日志、会话记录或凭据纳入公开仓库。
4. 不把一次性快照冒充实时文件系统，也不把 schema 合法冒充真实执行成功。
5. 不在缺少所有者、用途、范围或回滚证据时追求自动化。
6. 不把无界全机采集、后台监控、自动整理或 cfg-tidy apply 作为采用本框架的前置条件；但全机治理的规则、共享信息和统一索引必须有明确的覆盖模型与刷新责任。

一次治理任务完成的必要条件：范围与授权已写明；元数据盘点记录覆盖边界和跳过项；对象分轴分类并带证据；权威位置与副本关系可解释；所有变更先有 dry-run；写操作处于有界事务内；执行后核验真实后置状态；证据与回滚位置留在本地受限区；unknown、hold、outcome_unknown 如实保留。

## 2. 用户视角与完成条件

| 视角 | 主要问题 | 完成条件 |
| --- | --- | --- |
| 普通用户 | 文件在哪、为什么这么放、产物去哪、误动了怎么撤回 | 一次查询得到可读路径和来源；临时/交付/证据落点可解释；预览后再操作；一条命令撤销；错误信息说明原因与下一步，不要求理解 schema |
| 专业用户 / 管理员 | 批量整理、权威副本、索引新鲜度、部分失败 | 有界批次、dry-run、逐项哈希、冲突 hold、部分失败保守恢复、陈旧清单标记、重建协议和证据链 |
| 开发者 | 接口稳定、可测试、可嵌入 | 稳定 schema 标识、CLI/API 语义、版本与弃用策略、合成夹具、契约测试、发布白名单和回归门槛 |
| 企业 / 合规用户 | 责任分离、审计、保留、数据边界 | RBAC 映射、不可抵赖审计链、retention 与 legal hold、密钥与日志边界、SLA、可观测性、合规证据导出 |
| 多 Agent 协作 | 谁读、谁写、谁重建、谁裁决冲突、产物放哪 | 单一规范源、任务信封、工作区/产物类别、锁/广播边界、稳定操作 ID、并发重建规则、共享索引事务由宿主指定责任方执行 |

## 3. 可验收指标

以下指标必须在合成基准或用户明确授权的基准语料上测量；不得用本机真实清单作为公开测试夹具。

1. 可找性：在约定基准语料上，从任意工作目录用一条查询命令得到绝对路径，p95 不超过 1 秒；结果包含 root、kind、bytes、mtime 或明确标注缺失。
2. 新鲜度：索引与真实文件系统的偏差不超过一个刷新周期；每份清单有 snapshot id、generated_at、覆盖根、跳过项、过期标记和 retired_at，重建失败时旧清单仍可读取但不能冒充最新。
3. 可恢复性：所有合成写批次都能用一条 rollback 命令恢复到验证过的原状态，无需人工拼接命令；部分失败的已应用项作 best-effort 逆序恢复，失败项仍为 unknown，顶层状态保持保守。
4. 工作区与产物可追踪：临时文件、中间产物、交付物、证据、回滚副本、缓存、私有索引和 manifest 能按 task/workspace 关联到逻辑落点、状态、保留条件和验证证据；使用版本化 task-handoff Schema 与关系语义校验，并以合成宿主测试隔离 temporary/working/evidence/rollback/cache/private_index/manifest；不把真实路径或受限内容放进公开夹具。
5. 组织效果（可选观察项）：授权根目录下散落文件数、未知分类数、未裁决重复簇数有基线、有趋势；只汇报变化，不把百分比目标当治理结论。
6. Vault-backed 边界：adapter 只接收非秘密参数和 opaque credential reference；目标与操作受 allowlist 限制；凭据值、认证头和解析输出不进入模型、文件或日志；未配置或未验证时明确报告未部署。
7. 隐私边界：公开树扫描 100% 通过，发布包白名单不含本地交接、private 记录、真实清单、日志、凭据或会话文件；报告只用计数、哈希、脱敏名称和错误类型。
8. 工程可信度：npm test、npm pack --dry-run、契约/公开边界/执行器测试全部通过；测试覆盖计划、冲突 hold、哈希校验、回滚、结果未知和权限越界。
9. 快速检索：合成基准上，二级索引的 p95 查询延迟显著低于线性扫描；索引通过源清单字节数与 SHA-256 验证新鲜度，stale 时报告原因并安全降级，不把旧索引当实时结果。
10. 重复簇：相同算法/摘要的索引记录只生成 REVIEW_ONLY 候选，hold、retired、secret 或未分类指纹默认排除；权威建议只依据显式生命周期/角色优先级，绝不自动删除、覆盖或降级。
11. 增量刷新：快照差异必须显式产出新增、变更、删除 tombstone 和跳过项；指针切换前检查预期版本，切换后可按原指针回退，且任何快照都不能冒充实时文件系统。
12. 分类建议：只根据名称、目录上下文、已有记录与版本控制状态给出置信度和理由；输出始终为 dry-run，unknown 与 hold 必须保留，任何建议都不得直接移动、覆盖或删除文件。
13. 普通用户可用性：一条查询得到路径和来源，预览/建议/重复簇均只读，撤销只需 manifest 路径；错误码包含含义与下一步，结果摘要不要求用户理解 schema 或哈希细节。
14. 第三方共存：搜索、同步、版本控制工具只提供证据或只读结果；不复制凭据、不扩大授权，不把第三方输出当权威；写操作仍由有界事务与回滚证据控制。
15. 发布工程：CI 执行测试、发布包与 diff 检查；CHANGELOG、SECURITY、CONTRIBUTING、CODEOWNERS 与许可证/第三方来源边界可发现，不把本地证据当发布资产。
16. 开发者体验：稳定 exports 对应公开模块，错误码可与用户文档交叉核对；依赖来源、锁文件与发布白名单可审计，合成 benchmark 可重复运行。
17. 企业控制：逻辑角色默认拒绝未授权动作，审计链可检测事件/链接篡改，retention/legal hold 只给出 HOLD/KEEP/REVIEW 决策且永不删除，SLO 与证据导出只含脱敏本地数据。

## 4. 成熟度门槛

| 门槛 | 名称 | 必须交付 | 失败关闭条件 |
| --- | --- | --- | --- |
| M0 | 契约完整 | 产品定义、命名与分类判据、权威与新鲜度、生命周期/删除语义、schema 标识与迁移策略、逐步执行清单、文档链接测试 | 缺少完成条件、枚举无判据、权威/冲突无 tie-break、公开文档出现机器真实信息 |
| M1 | 可复现索引与可选执行 | 清单检索、freshness、dry-run、可选有界事务、备份、哈希、回滚、保守状态、合成测试、发布白名单 | 把清单当实时、覆盖目标、跟随链接、越界根、成功仅凭退出码、失败后无法恢复或误报成功 |
| M2 | 可运营的四层框架 | 增量刷新、倒排/FTS 或等价快速索引、基准、工作区/产物合同与版本化交接 Schema、合成宿主隔离测试、重复簇、分类建议仅 dry-run、普通用户入口、错误码表、第三方工具适配示例 | 每次查询全量扫描主清单、陈旧索引无标记、产物没有落点或交接状态、manifest/index 进入 Git、建议直接改文件、错误只暴露堆栈 |
| M3 | 企业化宿主集成 | CI、tag/release、CHANGELOG、SECURITY、CONTRIBUTING、CODEOWNERS、类型声明、API 稳定性、覆盖率、benchmark、fuzz、SBOM、RBAC、审计链、retention/legal hold、SLA、可观测性、国际化、vault adapter 合同和部署验证 | 无发布/recall 流程、审计可改写、无法证明边界、凭据进入模型/日志、合规状态只靠口头声明 |

门槛按顺序验收；低一级未通过时，不允许用高一级功能数量掩盖。每个步骤都必须有：范围、完成条件、验证命令、证据位置、回滚路径、剩余不确定性。

## 5. 证据与判定原则

当前文件系统实测优先于旧快照、旧报告和会话摘要。哈希只证明指定时点内容一致，不证明用途、授权、入口切换或可删除性。exit code 为 0 不等于后置状态正确；schema-valid 不等于运行时安全；报告、计划和台账只记录已验证事实，推断单列。任何受限访问、永久删除、外部发布、历史重写或全机共享索引修改都必须另按宿主边界取得明确授权。
