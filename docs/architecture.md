# 架构定位与边界

本文是公开框架合同，不是某台机器的实时部署报告。它说明哪些规则由本仓库定义、哪些能力由宿主适配器提供，以及哪些状态必须留在本机受限位置。

## 1. 产品定位

本项目是一个面向整台电脑的**文件治理、信息共享与统一索引框架**，供人和多个 Agent 共同使用。它不只是一个 Skill，也不是全机自动整理器：这里的“全机”指治理规则和索引覆盖范围，不代表后台无条件自动搬运。

Skill.md 是 Agent 的入口规程；仓库整体还包括全机治理规则、共享信息与索引契约、工作区/产物生命周期规则、参考实现和 vault-backed 适配边界。前两项是产品主线，工作区/产物是 Agent 运营落地，vault-backed 是可选安全支撑。移动、改名、归档和删除只是某些任务可能采用的受控动作，不是项目的成功指标。

## 2. 四层架构

| 层 | 负责什么 | 本仓库提供 | 宿主仍需提供 |
| --- | --- | --- | --- |
| 全机文件治理规范（产品主线） | 规定整台电脑的范围、owner、role、privacy、lifecycle、canonical、证据、hold、回滚和公开边界 | SKILL、分类规则、治理模型、Schema、成熟度标准 | 当前任务授权、实际路径语义、应用/系统所有权和责任方裁决 |
| 全机统一索引与信息共享（产品主线） | 让人和多个 Agent 按同一份受控元数据查找、解释、交接文件，并识别旧路径、陈旧索引和 tombstone | 索引 Schema、cfg-find、二级索引、增量刷新、查询报告、交接合同 | 经过授权的清单或宿主采集器、清单保存位置、刷新调度和真实文件系统核验 |
| Agent 工作区与产物边界 | 让临时文件、中间产物、最终交付物、证据、回滚副本、缓存和本地索引各有落点 | 产物类别、落点、命名、保留和交接合同 | 项目工作区映射、宿主目录、忽略规则、备份介质和清理责任 |
| Vault-backed 非明文调用 | 让 Agent 使用已授权服务而不接触密钥明文 | 使用规范、适配器最小合同、脱敏和审计边界 | 真实保险库、解析器或 broker、服务端 allowlist、轮换/撤销、OS 权限和运行时实现 |

前两层决定项目“是什么”：全机统一规则加上可重建、可解释、可共享的索引。第三层保证 Agent 按这套规则工作，第四层只解决调用外部服务时的凭据暴露问题；不能用第四层的宿主验证替代前两层的主线建设。

## 3. 数据流与权威关系

1. 全机范围先按目录职责、所有权、隐私和生命周期划分 canonical roots；“全机”表示规则和索引覆盖整台电脑，不表示无条件扫描或搬运所有文件。
2. 用户或宿主在具体任务中确定授权根、项目工作区和允许的操作类型。
3. 索引层消费授权的元数据 manifest；manifest 可以来自宿主适配器，也可以由已有受控工具生成。采集器是宿主接入点，不改变统一索引的公共语义。
4. 人和多个 Agent 通过同一索引查找、解释、关联和交接文件，不把旧快照当成实时文件系统。
5. Agent 将过程文件和结果放入对应产物槽位，并记录来源、生成关系、验证证据和保留条件。
6. 只有任务确实需要文件变更时，才生成 dry-run 计划并交给有界事务适配器；apply、rollback 和 outcome_unknown 都是可选的受控执行路径。
7. 凭据调用是一条独立边界：Agent 只提交非秘密参数和 opaque credential reference，vault-backed adapter 在本机完成解析和目标请求；凭据值不进入索引、产物、日志或模型上下文。

## 4. 能力状态词

- **规范合同**：必须遵守的字段、边界、状态和失败关闭规则。
- **参考实现**：仓库中可运行的 validator、index、report 或事务代码；它不等于宿主已经接入真实机器。
- **宿主适配器**：连接具体操作系统、项目目录、索引采集器、保险库或服务的实现；可由仓库外提供。
- **已部署能力**：只有在当前宿主完成配置并有可复核验证时才可声明；不能凭文档、Schema 或 worker 回执推断。

## 5. 明确非目标

1. 不默认无界全盘扫描、后台监控、自动搬运、自动去重、自动删除或强制集中所有文件；全机治理通过统一规则、授权清单和索引覆盖，而不是靠无界自动化。
2. 不把仓库根目录、系统临时目录、Downloads、桌面或任意 Agent 私有目录当作默认交付区。
3. 不把 GitHub 当作真实机器索引、manifest、运行证据或密钥库；公开远端只保存通用框架。
4. 不新增虚构的 vault export、CLI 或密钥值；没有宿主适配器时，只能报告“规范已定义、部署未验证”。

## 6. 公开与私有分流

公开 Git 可包含规则、Schema、合成夹具、脱敏示例和不依赖真实机器的参考代码。真实路径、目录清单、索引快照、交易 manifest、回滚副本、运行日志、账户信息和凭据必须留在宿主受限位置。真实 vault 的位置、密文和解锁材料不属于本仓库交付物。

成熟度判定必须分别报告四层的状态，不用索引工具数量或文件移动数量替代整体结论。
