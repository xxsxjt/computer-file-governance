# Agent 首次接入与持久引导

## 目标

用户第一次把本 Skill 的文件路径或仓库 URL 发给 Agent 后，Agent 不应只在当前会话临时读取。应把该路径登记到会在后续会话自动加载的持久指令入口，让用户不必重复发送。

## 首次接入步骤

1. 以用户给出的路径/URL 为准，读取完整 `SKILL.md`，并继续读取其引用、与任务相关的规范文档。无法访问时说明具体缺口，不猜内容。
2. 找出当前机器真正自动加载的全局 Agent 启动入口，以及哪些 Agent 确实会读取它。不要把“文件存在”当作“Agent 已加载”。
3. 若所有目标 Agent 共用一个自动加载入口，在该入口增加一条简短、持久的指针，要求每次新会话启动时读取这份 Skill；不复制整篇正文。若不存在共用入口，则在各 Agent 官方支持的全局指令入口分别增加同一指针。
4. 指针优先使用该 Agent 稳定可访问的本地规范副本；跨机器时使用用户给出的仓库 URL 或其正式 clone。不要把某台机器的个人路径写进公开仓库。
5. 检查自动加载入口里是否有与新规则冲突的旧条目。按当前明确用户指令更新冲突文本，保持核心 Skill 为唯一规则正文；认证凭据相关行为遵循 [非明文凭据规范](credential-use.md)，不得另加仅因 provider 名称而拒绝调用的规则。
6. 保存后通过 Agent 原生的 reload、新会话或等效启动检查，确认入口实际被加载且 Skill 正文可读。只有逐一核验过的 Agent 才报告为已接入；未核验者明确列出。
7. 把稳定指针和验证结果写入持久索引/工作记录，而不是仅记在会话记忆里。之后该 Agent 每次从自动加载入口发现指针，无需用户再次发送路径。

## 环境变量说明

环境变量只是提供一个值。只有 Agent 的正式启动指令、启动器或加载器明确读取该变量并加载指定文件时，它才会导致文档被读取。不要只设置一个名称新造的变量，然后声称 Agent 已自动加载。优先复用已有的统一入口和已支持的环境变量；除非用户明确要求，不新增 shell hook、启动服务、ACL、provider gate 或其他技术隔离。

## 范围与限制

- 指针只能自动覆盖实际读取同一入口的 Agent。若各 Agent 的启动链不同，就必须分别接入并逐一验证；没有跨所有 Agent 通用的文件名或环境变量。
- 文档指针属于行为规范，不是代码级强制执行。Agent 可能忽略未加载的指令；如没有启动加载证据，不得声称“所有 Agent 已自动读取”。
- 持久加载 Skill 不会自动注册新 MCP、Extension 或凭据适配器。Agent 要调用某个本机工具，仍需该工具已按用户配置接入；不能因工具未出现就要求用户把凭据贴进模型。
