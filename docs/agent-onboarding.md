# Agent 首次接入与单一事实源

## 目标

用户第一次把本 Skill 的文件路径或仓库 URL 发给一个 Agent 后，该 Agent 应完整读取规范，并把**同一份规范的指针**登记到自身会自动加载的持久指令入口。后续会话从该入口读取同一规范，用户不必重复发送路径。

统一仓库/用户指定的规范目录是唯一事实源。Agent 私有配置目录只存短指针，不存第二份 Skill 或其引用文档。

## 首次接入流程

1. **限定当前任务范围。** 用户把路径发给哪个 Agent，本轮就只为哪个 Agent 做持久登记。先判断该 Agent 是否确实读取一个全机/用户级共享入口；若已实测共享入口覆盖当前 Agent，优先在那里登记一次指针。否则只改当前 Agent 自己的自动加载入口。不要顺带盘点、配置或安装到其他 Agent；只有用户明确扩大范围时才处理它们。
2. **确定唯一源。** 用户提供的本机 Skill/repository 路径就是规范源；仓库根目录中的 `SKILL.md` 是主入口。若用户只给 URL，使用用户指定或已存在的统一本地 clone。存在多个 clone、路径不稳定或本机不可访问时，先询问应使用哪个统一位置，不要自行复制到 Agent 私有目录。
3. **完整读取。** 从该唯一源读取 `SKILL.md` 全文，并从同一规范目录读取它引用的文件。记录仓库 revision/commit，避免把旧快照误当当前版本。
4. **只登记指针。** 优先在当前 Agent 确实会读取的共享自动加载指令中写入主入口绝对路径；没有经过验证的共享入口时，写入当前 Agent 自己会自动加载的全局指令。要求相关任务开始时读取主 Skill 及其引用。不要把 Skill 正文、引用文档或整个 repository 复制/vendor 到 Agent 的私有 skills、plugins、prompts 或配置目录。
5. **原生目录不是第二事实源。** Agent 的原生 Skill 目录只是可选的加载适配位置，不是规范目录。若原生 loader 必须从该位置发现入口，只能使用指向唯一源的轻量 pointer/stub，或官方明确支持且验证过的 link；不得复制完整内容。原生机制不支持引用外部规范目录时，优先使用其自动加载的全局指令直接引用绝对路径；仍无法读取就报告限制，不制造副本。
6. **处理冲突但不扩张范围。** 检查当前 Agent 自动加载入口中与新规范直接冲突的旧规则；仅在本次授权范围内按最新明确用户指令修正。不要借此重构其他 Agent 的启动链。凭据规则遵循 [非明文凭据规范](credential-use.md)，不增加基于 provider 名称的拒绝门。
7. **验证持久加载。** 保存后用当前 Agent 的官方 prompt/debug 检查、reload 或新会话确认：全局入口确实加载，指针指向唯一规范源，相关任务会读取该主 Skill。再检查没有遗留的活动副本。无法运行 reload/新会话时，说明需要用户重启验证，不能声称已验证。
8. **记录可维护状态。** 记录规范源路径、commit、指针位置、验证证据和未覆盖的 Agent。以后更新规则只更新唯一源，并更新该源的 commit/revision；所有 Agent 继续读取同一路径，不进行逐个复制同步。

## 后续更新

- 规范变更只在唯一源仓库中编辑和版本控制；Agent 私有目录中的短指针保持稳定。
- 每次相关任务都读取该路径当前内容，不依赖安装时的副本或缓存。
- 若统一 clone 尚未包含用户指定的远端更新，按仓库的常规授权流程更新该 clone；不要另建 Agent 私有 clone。
- 如发现历史安装副本，先确认唯一源完整且可访问，再将副本移出自动加载/Skill discovery 目录，保留可回滚记录；不得继续把它当作规则来源。

## 环境变量

环境变量只保存字符串。只有 Agent 的自动加载指令或启动器明确读取变量，并据此打开规范文件，它才会触发读取。不要只设置变量就声称已接入。优先在当前 Agent 的持久指令中登记规范路径；除非用户明确要求，不新增全局 shell hook、启动服务、ACL、provider gate 或其他技术隔离。

## 边界

- 没有跨所有 Agent 自动生效的通用指令文件名或环境变量；本流程每次只接入当前 Agent，其他 Agent 需由用户另行指定。
- 这是一项行为规范，不是代码级强制执行。只有验证了实际启动输入的 Agent 才能报告为已接入。
- 持久加载规范不会自动注册 MCP、Extension 或凭据工具。工具未接入时，不能要求用户把凭据粘贴到模型。
